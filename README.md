# S3-Platform Design

PlantUML sources and rendered images describing the S3-Platform.

## Layout

```
.
├── *.puml              # Diagram sources (committed)
├── out/                # Rendered PNG + SVG (auto-generated by CI)
├── scripts/test.sh     # PlantUML syntax check used by CI
└── .github/workflows/  # CI: test + render + commit out/
```

## Scope

These diagrams describe the seven core S3-Platform repos:
`s3p-web-annotation`, `s3p-tape-service`, `cloud-core`, `s3p-database`, `s3p-node`, `s3p-sdk`, `s3p-n8n`.

External components included where load-bearing:

- `s3-platform-inc/s3-platform-plugin-template` (GitHub scaffold used by plugin authors).
- `s3p-simple-api` (HTTP shim between n8n and s3p-database, shipped from the s3p-n8n compose stack).
- GitHub Actions CI (builds plugin releases and uploads them to the platform S3 bucket).
- Platform S3 bucket (object storage for built plugins).
- GHCR (container registry).
- Redis (used by s3p-tape-service).

## Local rendering

Requires PlantUML and Graphviz:

```sh
sudo apt-get install -y plantuml graphviz   # Debian/Ubuntu
brew install plantuml graphviz              # macOS

bash scripts/test.sh                        # syntax check
plantuml -tpng -o "$(pwd)/out" *.puml       # render PNG
plantuml -tsvg -o "$(pwd)/out" *.puml       # render SVG
```

PlantUML's built-in Smetana layout (`!pragma layout smetana` at the top of the file) is used where Graphviz isn't available locally, so the diagrams also render without `dot` installed.

## CI

`.github/workflows/render.yml` runs on every push to `main` and every PR:

1. Installs `plantuml` + `graphviz`.
2. Runs `scripts/test.sh` (PlantUML `-checkonly`) to validate syntax.
3. Renders all sources to `out/` as PNG + SVG.
4. Uploads `out/` as an artifact.
5. On push to `main`, commits the refreshed `out/` back with `[skip ci]`.
